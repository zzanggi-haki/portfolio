- **13쪽 예시 상자**: "라벨링이 빠진 포인트를 화면에서 하나씩 눈으로 찾아야 했음" — 세션 개선 항목(누락 포인트 시인성 개선)에서 거꾸로 만든 예시
- **16쪽 결정 기록 근거 칸**
  - 1행 유효성 검사: "프로젝트가 다양해지며 개별 설정 방식으로는 확장이 어려움" — 카드의 "프로젝트 다양화에 확장 가능"을 근거로 풀어 씀

- **15쪽 LG 온프렘**
  - (16쪽으로 이동) 숫자 그대로 3·수정 9·신규 19는 기능정의서 v1.3 변경 여부(X/O/NEW) 집계, 취소선 행 2개(전체 모드 잘린 선 생성·수정) 제외 31개 기준. 모드별로 반복되는 속성 패널도 1개씩 셈
  - 취소선을 '범위에서 뺌'으로 해석함(밝기·대비·채도 조절, 코멘트, 상위 폴더 이름 표기, 결과 저장/나가기, 인스턴스 복사 등)

## 리드 PO 관점에서 남은 약점

1. **사례 03 해결(14쪽)** — 성과가 기능 목록이라 "그래서 효율이 얼마나 올랐나"가 없음. 세션 출신 개선의 체감 효과(예: 작업 시간, 오류 감소)가 기억나면 숫자 한 줄 추가 권장
2. **LG 온프렘(15쪽)** — 이미지 없음. 납품 화면을 쓸 수 없다면 지금처럼 글 3칸으로 충분하지만, "최소 수정"이 얼마나 최소였는지(예: 바꾼 화면 수, 재사용 비율)가 있으면 결정이 훨씬 설득력 있음
3. **결정 기록(16쪽)** — 리드 PO가 가장 좋아할 장. 각 결정의 "결과"가 아직 계획 수준인 행(성능 개선 로드맵, 모달 대체 여부)이 있음. 실제로 어떻게 끝났는지 알면 보강
4. **AI 전환(18 ~ 20쪽)** — 미수주 제안이 사례 01이라, AI 전환 장의 첫인상이 "결과 없음"으로 읽힐 수 있음. 순서를 교육(진행 중, 실적 있음) → 프레임워크 → 제안으로 바꾸는 것도 방법
5. **UX 장(21 ~ 25쪽)** — 사례 01(씽씽)만 2장, Amway·정관장은 1장. 이미지가 산출물(와이어프레임)이라 결과가 눈에 덜 들어옴
6. **이미지 중복 없음** 확인함. BMW BEV · Bosch 실제 화면은 아직 없음(9쪽은 설명 도식으로 대체)
