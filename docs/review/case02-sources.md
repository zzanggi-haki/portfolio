## 1. 작업 유형: 폴리라인 포인트 (Polyline Point)

- **정의(원문 요지)**: 기존 Polyline 작업 유형에서 각 Point에 클래스와 속성을 추가로 라벨링할 수 있도록 개발한 작업 유형. **Polyline으로 차선을 라벨링하고, 차선의 분기점·잘림·가려짐 같은 추가 정보를 Point에 라벨링**한다.
- **적용 리소스(2024.05.28 기준)**: Single Image(vector)만 사용 가능.
- **설계 결정이 보이는 부분**
  - 기존 Polyline과 **같이 선택할 수 없는 별도 작업 유형**으로 분리
  - 포인트 클래스·속성은 폴리라인 클래스의 **하위가 아니라 독립**적으로 설정(공통/클래스별 속성)
  - 포인트는 ID 없이 폴리라인 하위 정보로 저장, 산출물에 `point_annotations`(점 번호·좌표·라벨·속성)로 포함
  - 클래스가 없는 포인트는 라벨을 표시하지 않음, 포인트 클래스 초기화 시 점은 남김
  - **자르기**: 두 점 자르기 / 한 점 자르기 → 인스턴스 분리(왼쪽은 기존 ID, 오른쪽은 새 ID)
- **스튜디오 설정 5종**: 디폴트 포인트 지름(배포 2024.03.25), 첫번째 선 표시(2024.05.27), **포인트 RV 속성값 매핑(2024.03.25)**, 포인트 디폴트 클래스, 포인트 라벨 표시

## 2. BMW BEV — 포인트 RV 속성값 매핑 (2024.03.25 배포)

- 디폴트 포인트 지름과 **같은 Asana 태스크**로 배포됨 → 과제 목록의 「[프로젝트] BMW : BEV 프로젝트 타임라인 매핑」(2024.03.04 ~ 2024.03.25)과 같은 시기
- **기능**: 포인트의 속성값(예: `timestamp`)과 RV(참조 이미지) 파일명이 같으면 둘을 연결
  - 라벨링 프로젝트(폴리라인 포인트)에서 **포인트를 선택하면 매핑된 원본 이미지로 RV가 바뀜**
  - RV 이미지를 바꾸면 매핑된 포인트가 선택됨
  - 전처리 요청으로 각 포인트의 `timestamp` 속성에 RV 이미지 파일명을 넣어 사용
- 해석: 여러 장을 이어 붙인 BEV 이미지 위의 지점과, 그 지점을 찍은 **원본 주행 이미지를 서로 오가며 확인**하게 한 것
- 이후 서포트: BMW BEV 폴리라인 자르기 개선(2024.04.19 ~ 2024.04.29)

## 4. Arbe — 포인트클라우드 작업 유형 Polygon

- **정의**: 포인트클라우드 리소스에서 Polygon으로 라벨링하는 작업 유형. 3D 포인트클라우드에서 도로 영역 같은 공간을 라벨링.
- **예시(원문)**: **ARBE Free Space Mapping — 3D 환경에서 주행 가능한 도로 영역을 라벨링**
- **적용(2024.07.23 기준)**: Point Cloud(LiDAR, Radar)
- **설계 결정이 보이는 부분**
  - 인스턴스는 **Top view에서만 생성**(점 3개 이상), 점 이동은 Top view x·y / Rear·Side y·z
  - 라벨링 설정에서 **3D Cuboid · Segmentation과 같이 선택할 수 없음**
  - 미니뷰 Ego vehicle 표시 설정, FOV 표기·각도 설정(서포트 2024.07)
- 과제 목록: [데모] 폴리곤 단면 생성, z값 0(2024.03.25 ~ 2024.04.16) → [신규] 폴리곤 작업 유형(2024.03.25 ~ 2024.06.03)
