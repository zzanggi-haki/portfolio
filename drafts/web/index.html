검수 1건당 최소 10초 이상 단축 → 작업 단가 낮춤

검수는 모든 라벨링 작업이 반드시 거치는 단계입니다. 작업 건당 단가를 낮추기 위해 검수 화면에서 바로 수정하는 기능을 MVP로 내놓았고, 검수자 전원이 쓰는 기능이 되어 모든 리소스 유형의 검수로 확장했습니다.

역할
Product Owner (프로젝트 리드)
기간
2024.03 ~ 2024.11

AIMMO · 사례 01 · 문제

간단한 수정에도 화면과 작업자가 두 번씩 바뀌어
작업 효율이 떨어졌습니다

기존 뷰어는 작업 결과물을 한 눈에 보는 단방향 도구였습니다. 검수 중 수정이 필요하면 뷰어를 벗어나 작업 화면으로 넘어가 담당자를 바꿔야 했고, 작업자가 수정한 뒤에는 검수자가 다시 검수 화면에서 확인해야 했습니다.

간단한 수정 예시이 객체는 '자동차'가 아니라 '트럭' 클래스로 고쳐야 함

약 50초 ~ 1분간단한 수정 1건마다 더 들던 작업 시간최소 시간 합산 5 + 5 + 30 + 10초

AIMMO · 사례 01 · 해결 과정과 결과

검수자가 검수 화면에서 바로 고칠 수 있도록

해결 과정
  • 발견 — 작업 단가 효율을 높이기 위해 라벨링부터 재검수까지 전체 흐름을 살펴보다가, 검수와 수정 사이의 반복 작업에서 비효율이 생기는 것을 발견했습니다.
  • 판단 — 효과가 가장 클 것으로 본 방식을 MVP로 기획·개발해 실제 작업에 먼저 적용하고 테스트했습니다.
  • 확장 — 테스트에서 확인한 효과를 근거로 유관 팀의 협업을 이끌어내, 전체 리소스 유형으로 확장했습니다.
효과
  • 건당 검수 시간 최소 10초 단축 (작업 단가 낮춤)
  • 검수자 100% 사용 (효용성 검증)
  • 효용을 검증해 전체 리소스 유형의 검수로 확장 (2024.09 싱글 이미지 → 2024.11 씬 파일 → 전체)

BMW 5개년 계약 · Bosch 수주 기여 · 정식 작업 유형 출시

Bosch와 BMW가 제시한 고도화 라벨링 요구를 분석해 폴리라인 포인트라는 새 작업 유형으로 해석했습니다. 데이터를 가장 정확하고 효율적으로 만드는 작업 방식을 최소 기능 데모로 먼저 제안하고, 정식 작업 유형으로 출시했습니다.

AIMMO · 사례 02 · 문제

요구는 새로운 라벨링 방식 하나였지만,
실제로는 작업 방식 전체를 새로 설계해야 했습니다

요구를 그대로 기능으로 옮기면, 작업자는 이어 붙인 이미지 한 장을 보고 분기와 가려짐을 추측해야 했습니다. 그래서 라벨링 기능만이 아니라 작업자가 판단하고 검수하는 과정, 그 뒤의 데이터 전처리와 산출물까지 전체 프로세스를 고려해 기능을 이어서 만들었습니다.

고객 요구사항

“경로에서 분기점과 상태가 달라지는 지점을
구분해서 라벨링할 수 있게 해 주세요”

예: 차선이 갈라지는 곳, 실선이 점선으로 바뀌는 곳, 다른 차에 가려진 곳
해석한 것
  1. 선기존 폴리라인처럼 차선을 그린다
  2. 점의 의미선 위 포인트마다 클래스·속성을 붙인다
  3. 판단 근거각 포인트에서 그 지점을 찍은 원본 주행 이미지를 본다

판단이 어려운 예이 차선은 여기서 끊긴 걸까, 앞차에 가려진 걸까? 이어 붙인 BEV 한 장으로는 알 수 없음

BEV(Bird's Eye View) · 주행 사진들을 위에서 내려다본 시점으로 이어 붙인 한 장의 이미지

AIMMO · 사례 02 · 해결 과정과 결과

데모 기능으로 작업자와 함께 실제 작업 과정을 검증하고 출시

해결 과정
  • 데모 — 기한이 짧아 개발팀과 바로 붙어, 해석한 세 가지(선 · 포인트별 클래스·속성 · 원본 이미지 매핑)만 담은 최소 기능 데모를 만들었습니다.
  • 검증 — 실제 작업자들과 데모 기능으로 작업과 검수를 해 보며, 실제 작업 환경과 과정에서 정확하게 판단하고 라벨링할 수 있는지 확인했습니다.
  • 출시 — 검증한 방식 그대로 폴리라인 포인트를 정식 작업 유형으로 출시하고, BMW BEV 프로젝트에 적용한 뒤 자르기 등 운영 중 나온 요청을 보완했습니다.

AIMMO · 사례 03

사용자 조사 세션으로
지속적인 개선 시스템 만들기

작업자·검수자 효율을 높이기 위해 프로젝트 PM, 실제 작업자와 함께하는 주 1회 사용자 조사 세션을 직접 설계·진행해 약 1년간 운영했습니다. 세션에서 나온 병목을 다음 주 배포로 연결해, 실제 작업 효율을 높이는 기능을 계속 내보냈습니다.

역할세션 설계·진행, 개선 우선순위 결정기간약 1년 (현대자동차 개선 2024.03 ~ 2024.07)함께프로젝트 PM · 작업자 · PD · 개발팀
배경

라벨링 작업 단가를 낮추는 것은 에이모의 미션 중 하나였습니다. 기능을 애자일하게 계속 개선해야 했지만, 작업자는 익숙해진 방식 안에서 불편이나 비효율을 스스로 알아차리기 어려웠고, 그걸 함께 찾아낼 기회와 환경도 부족했습니다.

세션 설계
  • 프로젝트 PM과 실제 작업자를 매주 초대하는 세션을 직접 설계·진행 (주 1회 30분~1시간)
  • 실제 작업의 니즈와 불편을 듣고, 해당 기능을 함께 써 보며 개선 방향을 매주 수집
  • 수집한 내용을 PD와 바로 기능으로 설계해 다음 정기 배포에 반영하고, 효과를 보며 다시 업데이트
운영 루프
사용자 조사 세션→MVP 개발→매주 1회 정기 배포→다음 세션에서 실제 효과 확인→기능 고도화다른 프로젝트로 확장
성과

전체 작업 효율을 높일 개선 포인트를 세션에서 도출해 실제 배포까지 연결했습니다. 현대자동차 프로젝트 개선 10건(2024.03 ~ 2024.07)은 모두 세션에서 나왔고, 요청부터 배포까지 평균 약 2주가 걸렸습니다.

  • 포인트클라우드 세그멘테이션 — 라벨링 누락 포인트를 바로 찾도록 시인성 개선, 인스턴스 숨김·z값 필터링·올가미 선택으로 작업 범위를 빠르게 지정
  • 이미지 세그멘테이션 — 픽셀 누락을 검수 전에 자동 검출, 최대 확대 단축키·엣지 표시 개선으로 객체 핏 확인
  • 큐보이드·폴리라인 — 플랫큐보이드 확장면 시작점 조정, 폴리라인 첫째 선 표시
  • 썸네일 뷰어 — 인스턴스 크기(넓이·너비·높이)를 뷰어에서 바로 확인
